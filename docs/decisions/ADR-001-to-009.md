# Architectural Decision Records (ADR-001 through ADR-009)

## ADR-001: Two-Repository Architecture over Monorepo
* **Context:** The project requires a reusable open-source library (`mcp-workflow-adapter`) and a production vertical assistant (`alexa-plus-genomics-workflow-assistant`).
* **Decision:** Keep the two codebases as completely independent git repositories with separate package boundaries, pyproject configurations, and test suites.
* **Consequences:** Clean separation of concerns; the adapter library has zero clinical genomics dependencies and can be published as an independent PyPI package.

## ADR-002: Hexagonal Architecture (Ports and Adapters)
* **Context:** Core workflow state transitions, idempotency checks, and validation logic must be testable completely offline without AWS dependencies.
* **Decision:** Core package exposes pure ports (`StorageBackendPort`, `DomainPolicyPort`, `NotificationPort`, `OrchestratorPort`). Adapters implement these for SQLite WAL (`LocalBackend`) and AWS (`DynamoDBWorkflowStore`, `StepFunctionsReconciler`, `SNSNotificationSink`).
* **Consequences:** 100% offline unit/contract testability; zero AWS SDK imports inside core modules.

## ADR-003: Pure Side-Effect-Free State Machine
* **Context:** State transitions must be deterministic, auditable, and easily reconcilable across distributed processes.
* **Decision:** Implement state transitions (`CREATED` → `RUNNING` → `BLOCKED` → `COMPLETED`) as pure functions in `state_machine.py`. Every transition produces updated immutable dataclasses and audit event records without performing I/O.
* **Consequences:** Replay safety, simplified testing, and immunity to partial mutation corruption.

## ADR-004: Canonical SHA-256 Idempotency Engine
* **Context:** Unreliable voice clients or network retries might replay tool calls.
* **Decision:** Hash incoming mutation payloads with SHA-256 over recursively sorted keys (`idempotency.py`). Exactly identical payloads return the cached response with `duplicate: true`. Conflicting payloads for the same idempotency key raise `IDEMPOTENCY_CONFLICT`.
* **Consequences:** Absolute safety against duplicate state advancement and clear semantic contracts for conversational agents.

## ADR-005: Atomic Asset Exclusivity Locking
* **Context:** Two operators or voice sessions attempting to inspect the same asset (e.g. flow cell `FLOWCELL-WGS-07`) simultaneously could corrupt physical sample tracking.
* **Decision:** Enforce atomic asset exclusivity locks inside database transactions (`asset_locks` in SQLite, `PK=ASSET#<id>, SK=ACTIVE_LOCK` in DynamoDB). Complete operations delete the lock atomically.
* **Consequences:** Prevents concurrent inspection collisions across all sessions and threads.

## ADR-006: Multi-Session Disambiguation over Guessing
* **Context:** When a technician has multiple paused or active inspections and says "Resume my inspection", guessing the flow cell could cause catastrophic clinical errors.
* **Decision:** Refuse to guess. Return `AMBIGUOUS_ACTIVE_SESSION` error with the active execution briefs so the client disambiguates by flow cell or execution ID.
* **Consequences:** Safe, predictable multi-session handling adhering to clinical wet-lab standards.

## ADR-007: Domain-Neutral Extensible Policy (`DomainPolicyPort`)
* **Context:** The adapter must prove general applicability beyond healthcare.
* **Decision:** Parameterize step sequence, gate validations, and exception resolution rules through `DomainPolicyPort`. Prove with two completely distinct domains:
  1. Clinical Genomics WGS QC (`GenomicsDomainPolicy`)
  2. Industrial Centrifugal Pump Inspection (`PumpMaintenanceDomainPolicy`)
* **Consequences:** Proves open-source general utility with zero vertical domain coupling.

## ADR-008: Headerless HTTP 401 & Alexa+ Two-Tier OAuth 2.1
* **Context:** Alexa+ MCP clients expect compliant RFC 9728 discovery and OAuth 2.1 PKCE S256 verification without browser popup loops caused by `WWW-Authenticate` response headers.
* **Decision:** Strip `WWW-Authenticate` from HTTP 401 responses on `/mcp`. Serve protected resource metadata at `/.well-known/oauth-protected-resource`. Support two authorization tiers: `mcp:service` (discovery) and `mcp:tools` (mutations).
* **Consequences:** Protocol-accurate compatibility with modern conversational AI platforms.

## ADR-009: Dual Persistence Slices: Local SQLite WAL & AWS Single-Table DynamoDB + SFN
* **Context:** Developers need instant local iteration without cloud billing, while production requires elastic, highly available cloud execution.
* **Decision:** Provide two production-grade persistence slices:
  1. `LocalBackend`: SQLite with `PRAGMA journal_mode=WAL` and `BEGIN IMMEDIATE` transactions.
  2. `AWSBackend`: Single-table DynamoDB (`TransactWriteItems`) with asynchronous fenced Step Functions Standard reconciler (`R1`–`R8`).
* **Consequences:** Sub-20ms local execution, 100% offline verification, and enterprise-scale AWS deployment.
